### CÂU 4: Các header quan trọng nào cần thiết lập khi proxy (proxy_set_header) ? (Trang 2)
Dựa trên tài liệu nghiên cứu (**Buổi 8 Cấu hình NGINX reverse proxy – Upstream nhiều backend**), Các header quan trọng khi proxy: Mặc định NGINX không tự chuyển tiếp thông tin gốc của request, cần khai báo: proxy set header Host $host; proxy set header X-Real-IP $remote addr; proxy set header X-Forwarded-For $proxy add x forwarded for; proxy set header X-Forwarded-Proto $scheme; Giải thích: nếu không có các header này, backend sẽ thấy mọi request đều đến từ chính NGINX (127.0.0.1) thay vì IP thật của client, gây khó khăn khi cần log, rate-limit hoặc phân tích theo IP người dùng. [1] *(Trang 2)*.**

### CÂU 17: Tóm tắt tài liệu Buổi 8 này (Toàn bộ Trang 1-5)
Dựa trên tài liệu nghiên cứu (**Buổi 8 Cấu hình NGINX reverse proxy – Upstream nhiều backend**), nội dung chính được phân bổ theo các trọng tâm cốt lõi sau:

1. **Mục tiêu Hiểu rõ**: Mục tiêu Hiểu rõ vai trò của Web Server và Reverse Proxy trong kiến trúc một hệ thống backend thực tế. [1] *(Trang 1)*.
2. **NGINX làm Reverse Proxy**: NGINX làm Reverse Proxy cho một cặp Frontend – Backend Kịch bản: Một domain duy nhất phục vụ cả frontend lẫn backend API — frontend ở /, API ở /api/, tránh vấn đề CORS vì client luôn gọi cùng một origin. [2] *(Trang 2)*.
3. **Server block chuẩn thường**: Một server block chuẩn thường gồm những gì: listen: Port lắng nghe (80 cho HTTP, 443 cho HTTPS). [3] *(Trang 3)*.
4. **Lưu ý quan trọng**: Lưu ý quan trọng: Chứng chỉ tự ký sẽ khiến trình duyệt cảnh báo "Not Secure"/"NET::ERR CERT AUTHORITY INVALID" vì đây chỉ để test cục bộ, không thể dùng thật trên internet. [4] *(Trang 4)*.
5. **Tài liệu tham khảo**: Tài liệu tham khảo Tài liệu chính thức: NGINX Documentation (nginx.org/en/docs/), tài liệu openssl req, tài liệu Certbot (certbot.eff.org). [5] *(Trang 5)*.**
